[Wikipedia](https://en.wikipedia.org/wiki/ASN.1) describes ASN.1
(Abstract Syntax Notation One) as _"a standard interface description language
for defining data structures that can be serialized and deserialized in a
cross-platform way"_. Which, whilst accurate, is not especially helpful.

A more intuitive way to understand ASN.1 is to imagine defining a simple message
type, such as a `Person` with a name and an age:

```
Person ::= SEQUENCE {
  name UTF8String,
  age  INTEGER
}
```

A corresponding JSON encoding might look like:

```json
{
  "name": "Bob",
  "age": 41
}
```

ASN.1 provides a formal description of data structures so different systems can
agree on their meaning. Notably, the schema is separate from the encoding,
allowing the same structure to be represented as compact binary, readable text,
or other formats while keeping the definition of each field unambiguous.

## Why I looked it up

I occasionally receive security advisories on GitHub for one of my projects.
Most of the time I simply update the affected dependencies, but every so often
I read the CVE to understand what the underlying issue is and whether
it affects my usage.

In this case, it was an exploit in `node-forge`, which is a Node.js cryptography
library.  [The vulnerability](https://www.kb.cert.org/vuls/id/521113)
involved specially crafted ASN.1 data that would bypass validation, even when
cryptographically incorrect.
